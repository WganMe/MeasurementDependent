# Measurement-Dependent Clustering in the Growing Urban Observatory Sensor Network

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23099939.svg)](https://doi.org/10.5281/zenodo.23099939)
[![License: CC BY 4.0](https://img.shields.io/badge/License-CC%20BY%204.0-lightgrey.svg)](LICENSE)

Companion repository for the manuscript submitted to **PeerJ**.

The submission itself is generated by `convert_to_peerj.py` into the sibling `PeerJ`
directory. `main.tex` and `main_si.tex` here are the sources it converts from.

Archived at Zenodo: **doi:10.5281/zenodo.23099939** (CC BY 4.0). That DOI is the
citable, permanent snapshot; this repository is the live working copy.

Every number and figure in the manuscript is regenerated by this repository.
No value is estimated, projected or borrowed: each analysis script writes a JSON
result file, and the text and tables read their values from those files through
LaTeX macros, so prose and results share one source.

**What this repository can and cannot reproduce — read before citing.** The chain
has three links, and they are not equally checkable:

* **committed results → manuscript.** Fully reproducible here. The supplement is
  regenerated from the committed `results_*.json`, and every macro in `main.tex`
  is checked against the JSON value it is read from, on every push.
* **benchmark snapshot → committed results.** Reproducible here. `urban_observatory.db`
  is committed, so the five analyses that read the instrument catalogue
  (`analysis_snapshot.py`, `analysis_snapdupes.py`, `analysis_feeds.py`,
  `analysis_exclusions.py`, `analysis_rarefy.py`) run from a plain clone and
  regenerate their committed `results_*.json` byte-for-byte. Set `UO_DB` to point
  them at a different copy.
* **archive → census index.** **Not** reproducible from this repository. The
  per-year census in `uo_archive_index.json` is derived from the Newcastle Urban
  Observatory archive, 73.8 GB across 884 files, which is Newcastle University's
  under CC BY 4.0 (doi:10.25405/data.ncl.c.5059913) and is not redistributed here.
  Rebuilding that index needs the archive: set `UO_ARCHIVE` to its root and run
  `build_archive_index.py`. The publisher **appends rows to files after they are
  first downloaded**, so the index depends on which snapshot was read.

`UO_ARCHIVE_MANIFEST.json` closes the last gap as far as it can be closed: it
pins the archive snapshot by listing all 884 members with their byte counts and
SHA-256, so a reader can establish whether their download is the one the census
came from. It does not make the census reproducible on its own.

A reader who wants to re-derive the census therefore needs two things this
repository does not carry — the archive and the publisher's cooperation on
versioning — but does not need this authors' machine.

Observatory collection is published independently by Newcastle University under
CC BY 4.0; see the manuscript's Data Availability statement.

`urban_observatory.db` is the one boundary case, and it is deliberately cut so
that it stays on the right side of it. It carries the instrument catalogue and
the *identity* of what was reported, but every measured quantity has been
nulled: no temperature, no NO2 reading, no traffic count. Nothing downstream
reads those values, and removing them changes no committed result. What remains
is a record of which instruments existed, where, and under which broker — the
subject of the paper, not the observatory's measurements.

`uo_archive_index.json` is the derived, per-year census index (identifier,
position, theme, first-seen date). It contains no readings and no credentials.

## Reproducing

Requires TeX Live (`pdflatex`, `bibtex`) and Python 3 with `numpy`, `scipy` and
`matplotlib`.

```sh
# 1. derived results and the supplement
python3 build_archive_index.py   # only if uo_archive_index.json is absent
python3 analysis_common.py       # frames, units, uncertainty
python3 analysis_multiscale.py   # multiscale estimator and controls
python3 analysis_tolerance.py    # merge-tolerance curve
python3 analysis_precision.py    # published coordinate precision and co-location
python3 analysis_trendtests.py   # correctly sized trend tests
python3 analysis_reframe.py      # support-matched windows
python3 make_supplement.py       # regenerate main_si.tex

# 2. documents
./build.sh
pdflatex main_si && pdflatex main_si && pdflatex main_si
```

`build.sh` runs the full manuscript build and checks that `main.pdf` parses,
because an interrupted `pdflatex` leaves a truncated PDF that `latexmk` still
reports as success.

Every random draw uses one fixed seed, stated in the manuscript.

## What the code is written to let you check

The manuscript reports several negative results, so the controls matter as much
as the estimates.

* **Known-answer controls.** The multiscale estimator is run on patterns whose
  answer is analytic — complete spatial randomness, a regular lattice, and a
  clustered pattern. These controls caught a real error: an earlier estimator
  applied a rectangular edge weight to a convex-hull window and returned a large
  spurious value where the answer is zero. That estimator is now withdrawn in
  code (`analysis_common.donnelly_ce`), and the correct form is in
  `analysis_donnelly.py`.
* **A control is a draw, not a value.** `analysis_envelope.py` runs 199
  complete-spatial-randomness realisations at three sample sizes. The residual
  bias is reported in metres (4.1 m at *N* = 561; 262.7 m at *N* = 39) rather
  than described as zero.
* **Equation check.** `analysis_gridorigin.py` verifies the Gini formula used in
  the paper against its textbook form over 2000 random count vectors.
* **Independent implementation.** `crosscheck_spatstat.py` re-implements the
  single-index and multiscale estimators and compares them with `spatstat`'s
  output (`crosscheck_spatstat.R`), so no result rests on one implementation.
* **Provenance.** `analysis_feeds.py` documents a join trap: the benchmark
  snapshot's `readings` table joins to its `sensors` table on the sensor
  *name*, not on the numeric `raw_id`. Joining on `raw_id` yields an empty
  intersection.

## Repository status

The GitHub repository is **private**. It is made public on acceptance; until
then, read-only access for review is granted by invitation. The manuscript cites
only the Zenodo DOI, which is public now, so nothing in the paper depends on the
repository's visibility.

Correspondence, editorial drafts and deposit notes are held in `admin/` and are
deliberately **not** tracked, so the repository is a code-and-results record
rather than a record of the review process.
